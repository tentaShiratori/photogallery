## 書き方

1 つの UC は 1 つの目的にする。名前は動詞で終える。主アクターはユーザー、アドミン、スクリプトのいずれか 1 つ。画面を見る UC はユーザー。アップロードはスクリプト。

必須の項目は、ID、名前、主アクター、事前条件、事後条件（成功）、事後条件（失敗）、フロー。ID は `UC-領域-番号` で、見出しと同じ。事前条件は、始まるときに既に成り立っていること。無ければ「なし」。失敗の道が無ければ、事後条件（失敗）は「なし」。

フローは 1 から番号を付ける。1 行は主語 1 つと動作 1 つ。主語は主アクターか、ブラウザか、スクリプト。画面の部品は主語にしない。

代替は、分かれた手順の直下に `- 3a.` と書く。次の代替は `- 3b.`。例外は `- 3e.`、次は `- 3f.`。その道の手順はさらに一段下げる。道の最後の行は、そのとき画面かコンソールに残る変化を書く。番号で別の手順へ戻るとは書かない。続く変化は、その道の中に書く。

事後条件は、その道の最後に残る変化だけを書く。フローの途中で消えるものは、フローに書く。

画面を見れば分かる並びや位置は書かない。別の条件から逆に分かることは書かない。ブラウザや動画の初期の挙動は書かない。実装、ファイル名、理由は書かない。

画面とコンソールの文言は「」で囲み、今の文字列のまま書く。用語は GLOSSARY.md の語を使う。

空でないときだけ足す項目は、トリガー、関連、未決。

```markdown
## UC-GAL-01 ギャラリーを開く

- ID: UC-GAL-01
- 名前: ギャラリーを開く
- 主アクター: ユーザー
- 事前条件: なし
- 事後条件（成功）:
- 事後条件（失敗）:

### フロー

1. ユーザーがギャラリーを開く。
   - 1a. 別の成功する道。
     1. ブラウザはその変化を行う。
     2. そのとき残る変化。
   - 1e. 目的が達しない道。
     1. ブラウザは失敗の変化を行う。
     2. そのとき残る変化。
2. ブラウザは成功の変化を行う。
3. そのとき残る変化。
```
